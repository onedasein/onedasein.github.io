# 00 · 方向选择：三方向轮转公测

> 目标：用 **6 周 / 3 个探针项目** 把"我好像喜欢 X"变成"数据显示我适合 X"。
> 适用：2026.9–2027.1（大二上）。做完再选，不许提前下结论。

---

## 0. 为什么不要现在选

- 你对三个方向的想象，全部来自二手信息（帖子、视频、别人说）。**没有亲手做过 30 小时，喜欢就是幻觉。**
- 大二是唯一一段"选错方向成本≈0"的时间窗口：没有实习、没有 KPI、没有 deadline。
- 三个方向 **共享同一条底座**（C / CSAPP / OS / 网络 / 并发 / 存储），无论最后选哪个，这 6 周都不亏。
- 更重要的是：**大二的真正目标不是选对方向，而是养成"能独立交付项目"的能力**。这个能力跨方向通用。

---

## 1. 轮转公测的三个探针

每个探针的设计原则：**30–50 小时、2 周、必须有一个可运行的东西、必须碰到该方向最"苦"的部分**（甜的部分谁都觉得好玩）。
顺序：先 A（打地基，同时服务另外两个），再 B，再 C。

### 探针 A：后端 / 系统（第 1–2 周，约 40h）

| 任务 | 说明 | 碰到什么 |
|---|---|---|
| A1 | 用 **C** 写一个 epoll 的 HTTP/1.1 静态文件服务器，支持 keep-alive | 非阻塞 IO、超时、缓冲区管理、EBADF/EPIPE 的真实折磨 |
| A2 | 用 `wrk` 压测，画出 QPS/延迟曲线；用 `perf` 找瓶颈，试着优化一轮 | 性能工程、火焰图 |
| A3（加分） | 用 **Go** 写一个小服务，注册到 etcd，做一次优雅重启 | 分布式协调、工程效率 |

**验收**：GitHub repo + README（含压测数据与优化前后对比）+ 200 字"哪里最爽/最烦"。
**苦点检验**：你能否忍受为 3% 的 QPS 提升花 5 小时看 perf 输出？

### 探针 B：AI Infra / HPC（第 3–4 周，约 40h）

| 任务 | 说明 | 碰到什么 |
|---|---|---|
| B1 | 用 CUDA 写 `reduce`、`sgemm` 两个 kernel，与 cuBLAS 对比 GFLOPS | SIMT、shared memory、occupancy |
| B2 | 用 `ncu` 剖析，报告 **Roofline 位置**、是否是 memory-bound | 性能建模、指标阅读 |
| B3 | 用 Triton 写一个 fused LayerNorm，和 PyTorch 对比 | kernel DSL、融合 |
| B4（加分） | 跑一次 7B 模型的 vLLM 推理，用 `nsys` 看一次 batch 的 timeline | 真实推理系统 |

**验收**：repo + 一张 Roofline 图 + 一张 ncu 截图 + "为什么我的 kernel 只有 cuBLAS 的 X%"分析。
**苦点检验**：你是否能接受**没有教程、只有文档和 profiler**，靠读指标盲调几条通宵？

### 探针 C：ML / Agent（第 5–6 周，约 40h）

| 任务 | 说明 | 碰到什么 |
|---|---|---|
| C1 | 跟着 Karpathy 的 nanoGPT 手写一遍，从零实现 attention + 反向传播 | 数学落地、张量调试 |
| C2 | 训一个字符级小模型（能跑通即可），画 loss 曲线 | 训练循环、诊断 |
| C3 | 写一个 mini agent：3 个工具（搜索/计算/文件）+ ReAct 循环 + 20 条自建 eval | 上下文管理、失败模式 |
| C4（加分） | 用 LoRA 微调一个 0.5B 模型做分类任务，对比 zero-shot | 对齐、数据工程 |

**验收**：repo + loss 曲线 + eval 报告（含失败案例分类）。
**苦点检验**：你是否受得了**结果不确定**——调半天不知道是数据、超参还是 eval 的问题？

## 2. 评分表（做完 3 个探针后填，凭当时的真实感受）

每项 1–5 分。**第 1–4 项是主观体验，第 5–7 项是客观现实。**

| 维度 | A 后端/系统 | B AI Infra/HPC | C ML/Agent |
|---|---|---|---|
| 1. 心流：做的时候是否忘记时间 | | | |
| 2. 耐受：遇到硬 bug / 看不懂的指标时，是兴奋还是想逃 | | | |
| 3. 自驱：没人教的情况下，我能自己推进多远 | | | |
| 4. 好奇：路上遇到的"为什么"是否真的想去查 | | | |
| 5. 岗位密度（本科可投的实习数量） | | | |
| 6. 稀缺性（同龄人里能做出来的人有多少，越少越高） | | | |
| 7. 可积累性（三年后这项技能还值钱吗） | | | |
| **合计** | | | |

### 决策规则（写死，防止反复横跳）

1. **主观 4 项之和**最高的方向 = 候选主攻；相差 ≤2 分视为并列。
2. 并列时，用 `主观分 × 稀缺性` 决出主攻（岗位密度只用来判断"能不能找到实习"，不用来选兴趣）。
3. **任何方向如果第 2 项（耐受）≤2 分，直接淘汰出主攻**——能力和兴趣都可以培养，耐受不能。
4. 决策输出物：**500 字决策备忘**，包含"我选 X，理由是数据，我的退出条件是……"，存到 `progress.md` 里。
5. 主攻一旦确定，**至少投入 9 个月再重新评估**；期间允许副线摇摆。

## 3. 三种合理结局（都不是失败）

| 结局 | 适合谁 | 后续路径 |
|---|---|---|
| **A 为主，B 为辅** | 喜欢系统的确定性，但想要差异化 | 最像"AI Infra/推理引擎/训练框架"岗，也是当前性价比最高的组合 |
| **B 为主，C 为辅** | 既爱硬件性能又爱模型 | 走"模型工程 / 算法工程 / 高性能推理" |
| **纯 A** | 只想把系统做深 | 存储、数据库、分布式中间件、云原生 —— 岗位最稳，天花板极高 |
| **纯 C** | 数学好、喜欢不确定性 | 但必须补上"工程能力"（否则只是调包），建议至少做完探针 A |

**千万不要**：三个都只做了一半，然后在简历上写"熟悉 XXX"。

## 4. 这 6 周的额外产出（跨方向通用，写进简历）

- 一个能讲 20 分钟的**技术故事**（选最有代表性的探针，讲清背景→方案→数据→反思）。
- 习惯：**每个项目都带 benchmark 数据和 README**。这个习惯比方向选择重要 10 倍。
- 一份"我不喜欢什么"的清单（同样值钱，能帮你砍掉很多弯路）。

## 5. 常见反模式

- ❌ 花两周读《深度学习》花书、看 CS231n，就把探针 C 标记为"喜欢"——**读书不是探针，动手才是**。
- ❌ 探针 A 只用 Python 写，避开 C —— 那测的是"你会不会 Python"，不是"你适不适合系统方向"。
- ❌ 探针 B 只跑别人的 repo，不写 kernel —— 那测的是"你会不会装环境"。
- ❌ 探针没做完就宣布结论。
- ❌ 一直拖着不选，用"我还在探索"当借口。**6 周后必须写决策备忘，哪怕写"我暂时选 A，退出条件如下"。**
